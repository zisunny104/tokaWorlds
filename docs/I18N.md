# tokaWorlds 多語系（I18N）

版本 1.1.0 起，所有使用者看得到的文字都抽到 `src/main/resources/lang/zh-TW.yml`，使用共用套件 `dev.toka:tokaI18n:0.1.0`（shade 進 jar，重新定位到 `dev.toka.worlds.internal.i18n`）。目前只有繁體中文，沒有 `en-US`。

- 語言：`config.yml` 的 `language`（預設 `zh-TW`），由 `Main` 持有 `Messages`，其他類別透過 `Main.messages()` 取得。
- 覆蓋：伺服器擁有者可把同名檔放進 `plugins/tokaWorlds/lang/`。
- 測試：`LangFileTest` 檢查語系檔每個 key 都能讀到、原始碼用 `t("…")`／`text("…")`／`lines("…")` 引用的 key 都存在、程式碼（註解除外）沒有中文字面值。

## key 數量與分區

共 129 個 key（126 個單行文字 + 3 個多行清單：`cmd.worlds.usage`、`help.worlds`、`msg.plan.footer`）。

| 區 | 內容 |
|---|---|
| `cmd.worlds.*` | 指令說明（desc）與未知子指令時的用法（usage） |
| `help.worlds` | `/worlds help` 的多行說明 |
| `msg.*` | 玩家／指令執行者訊息：待辦列表（`msg.plan.*`）、已加入／清空／檢查通過、排程、完成、停止、list、resend、維護與返回、舊編號物品通知 |
| `err.*` | 錯誤與拒絕（含世界名稱／路徑檢查、連動其他插件、用法 `err.usage.*`）；`err.show` 負責加上 `§c` 後顯示 |
| `ui.*` | 表單：`ui.menu.*` 主選單、`ui.add.*` 新增項目、`ui.confirm.*` 排程確認 |
| `log.*` | 後台文字，包含 `log.legacy.*`（舊編號物品） |
| `status.*` | 狀態字：操作名稱 `status.op.*`、連動標記與說明 `status.link.*`、`status.legacyRemoved` |
| `cli.*` | 離線工具 `StorageCli` 的輸出（純文字，不加色碼） |

## 每個指令的 help 位置

| 指令 | help 位置 | 說明 |
|---|---|---|
| `/worlds` | `help.worlds`（`/worlds help`；主控台不帶參數時也顯示） | 列出全部子指令：`list`、`mount`、`unmount`、`rename`、`plan`、`check`、`confirm`、`clear`、`cancel`、`resend`、`return`、`help`，以及遊戲內無參數開啟的管理視窗 |

`/worlds help` 需要 `tokaWorlds.admin`（與其他管理子指令相同）；`/worlds return` 是玩家可用的子指令，因此一併寫在 help 內。

## 顏色套用對照

| 位置 | 套用 |
|---|---|
| 後台 log | 不加方括號標籤；文字 `§b`、數字／名稱 `§a`、警告 `§e`、錯誤 `§c`（`log.*`） |
| 玩家訊息 | 文字 `§b`、變動值 `§a`、成功 `§a`、警告 `§e`、錯誤 `§c` |
| 錯誤顯示 | `err.show` = `§c${0}`；`err.*` 本身不含色碼，包進 `err.show` 才顯示（原本錯誤是 `§e`，已改為 `§c`） |
| help | 標題 `§6§l`、指令 `§e`、分隔 `§7-`、說明 `§b` |
| 表單 | 標題、按鈕、欄位不加色碼；待辦列表本文（`msg.plan.*`）含 `§b/§a`，Bedrock 表單可以顯示 |
| 寫入 `legacy-items.log` 的紀錄 | 純文字，不加色碼（`log.legacy.dropped`、`status.legacyRemoved`） |

## 保留在程式裡的非翻譯文字

- 指令名、子指令、權限節點、config key、`--link`／`--no-link`。
- 後台標記行 `WORLD_OPERATION_PASS …`、`StorageCli` 的 `IMPORT_PASS`／`MIGRATE_PASS`／`STATE_PASS` 標記：穩定的機器代碼，測試與維運腳本可能比對，不翻譯。
- `WorldState` 的資料驗證 Exception 訊息改為英文（給開發者看，資料損毀時才會出現）。
- 資料／API 內的 code：操作 `type`（`mount`／`unmount`／`rename`）、journal stage 等，顯示時才轉成文字（`status.op.*`）。

## StorageCli

`StorageCli` 是停服後在命令列使用的離線工具，但它的輸出對維運人員仍是使用者可見文字，因此一樣抽到 `cli.*`：以 `Messages` 讀 jar 內的 `lang/zh-TW.yml`（固定繁中，不讀 `config.yml`，也不讀覆蓋資料夾），不含色碼。

## 待確認

1. 錯誤顏色：原本所有錯誤用 `§e`，依慣例改成 `§c`（警告才用 `§e`）。「執行權限已移除」「世界仍有玩家」這類是拒絕，也用 `§c`。
2. `status.link.zero`／`status.link.portal` 的翻譯文字會被寫進 journal 的 `receipts[].description`（資料庫內的操作紀錄），與「資料不存翻譯後的字」衝突；為了不改變既有資料格式與行為暫時保留，之後若要多語言需改存 code 加參數。
3. 待辦列表原本直接顯示 `mount`／`unmount`／`rename`，現在顯示「掛載／卸載／更名」（`status.op.*`）。
4. `cli.*` 不在慣例的 key 分區內，是為 `StorageCli` 新增的區。
5. `WORLD_OPERATION_PASS` 等標記行不翻譯，是否也要依「後台不加標籤」慣例調整請確認。
6. `WorldPaths` 保留單參數建構子（`tests/smoke/WorldProbe` 使用），此時內部以 `zh-TW` 建立自己的 `Messages`，不讀插件的語言設定。
7. `plugin.yml` 新增指令 `usage: "/worlds help 查看說明"`（原本沒有），非管理員執行 `/worlds` 時核心會顯示這行。
8. `README.md` 開頭的版本號（1.0.5）原本就過舊，這次沒有改動。
